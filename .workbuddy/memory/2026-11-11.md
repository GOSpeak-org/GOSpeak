## 安全修复：策略契约 ↔ 传输通道 / OAuth 302 错误泄漏（对应 review_architecture_2026-11-10 B1/B2）

- 新增 `app/server/internal/policy`：传输无关的 `Evaluate(subject, action, domain)`。
  HTTP（middleware.BanCheck/GuestGuard）与 WS 共用同一判决源。封禁每次实时查库
  （域访客封禁只写 ban 行、不失效 JWT），只缓存 `IsGuest` 身份 2s 以避免
  typing/member:speaking 高频事件打 DB；ban 角色加字面量兜底，防 roleCache 空时 fail-open。
- WS 接入点：`ws.UpgraderConfig.ConnectPolicy`（握手补 BanCheck）、
  `ws.HandlerRegistry.SetPolicyGuard`（每条上行消息判决，命中封禁发 ACK 并 Close）。
  组合根 `server/ws_policy.go::installWSPolicy` 注入；域上下文只取 `Hub.ClientDomain`
  这个服务端登记值，不信任 payload 的 domain_uuid。
- signal 层二次判决：`resolveMessageRoom` 用 DB 的 roomDomainUUID、`OnTyping` 用
  splitRoomKey、`OnPrivateMessageSend` 用 ClientDomain 复查；访客白名单禁
  private:send / room:create / room:kick / 未知事件，对齐 HTTP GuestGuard。
- OAuth 三层：`handler.oauthErrorMessage` 只取 pkg.ClientError 的错误码 + 固定默认文案，
  禁止回传 AppError.Message；`redirectOAuthError` 清洗控制字符并按 rune 截断；
  service 不再把 err.Error() 塞进 OAUTH_* AppError；`pkg/oauth/redact.go` 对 httpDo
  的 *url.Error 脱敏 access_token 等敏感 query。
- 验证：`go build ./...`、`go vet ./...`、`go test ./...` 全绿；`-race` 覆盖
  server/policy/ws/signal/middleware。新增 6 个测试文件（policy、ws handler/upgrader、
  server ws_policy、signal policy_bridge、handler oauth_security、pkg/oauth redact）。
- 发现：原 middleware 的 `guestDomainReadPaths` 排在白名单之后，从未生效；本次保持
  既有行为（不在安全修复中放宽访客权限），已在 policy 注释说明。
- 环境：工作区存在并发编辑，gin.go 一度被回滚到 HEAD，已重新应用装配；
  router.go ↔ routes/system/routes.go 的 SystemUpdate 参数由并发方补齐后编译恢复。
