## 头像上传链路修复 + 裁切能力

用户反馈：头像上传链路有问题、且无裁切能力。

根因：前端 `app/web/src/api/storage.ts` 的 `uploadFile` 用 axios 发送 FormData。axios 实例默认 Content-Type 为 application/json，会把 FormData 序列化成 JSON；显式设 `multipart/form-data`（无 boundary）又会让服务端 `c.FormFile` 解析失败 → Local 模式头像/聊天附件上传实际是坏的（S3 直传分支本就用 fetch，正常）。

改动：
- `storage.ts#uploadFile`：改用原生 `fetch('/api/v1/storage/upload', {method:'POST', body: formData, credentials:'include'})`，由浏览器自动加 multipart boundary，并解析 `{code,msg,data}` 信封、非 0 抛错。同时利好 `MessageInput` 的聊天附件上传。
- 新增 `app/web/src/components/profile/AvatarCropperModal.tsx`：原生 Canvas 实现方形/圆形头像裁切（拖拽平移 + 缩放滑块/滚轮 + 圆形导出 512×512 PNG），零第三方依赖。
- `profileForm.tsx`：选图后先打开裁切弹窗，确认后再上传裁切后的 blob（presign/upload 走通用存储链路），预览+落库；失败 toast。

后端：未改动。注意 `app/server/internal/handler/user_handler.go#UploadAvatar` 是闲置的专用端点（前端从未调用，实际走通用存储 upload），可作为后续清理项。

校验：biome check 三文件通过；`tsc --noEmit`（app/web）通过。

## 下拉框走查：弹层异常修复（共享组件）

用户反馈迁移后「弹层异常」。根因全部在 `packages/components/src/components/select.tsx`（6 处下拉共用，改一处全生效）：

1. `SelectContent` 宽度没跟 trigger 绑定：`min-w-[8rem]` → `min-w-[var(--radix-select-trigger-width)]`，并加 `max-w-[var(--radix-popper-available-width)]`。
2. `SelectContent` 默认 `align="center"`，弹层比输入框宽时向两侧溢，看起来"错位" → 默认改 `align="start"`，`sideOffset` 提为可覆盖参数，加 `collisionPadding={8}`。
3. **上一轮在 Viewport 上加的 `max-h-72 overflow-y-auto` 是错的**：Radix 的 Viewport 自带 `position:relative/flex:1/overflow:auto` 并按可用空间写内联高度，自定义高度会和内联样式打架 → 列表被裁、滚不动。已全部移除，Viewport 只留 `w-full p-1`。
4. `z-[60]` → `z-[100]`（项目里 Dialog/菜单/遮罩普遍 z-50，避免被盖）。
5. `SelectItem` 高亮类从 `focus:bg-muted` 改为 `data-[highlighted]:bg-muted`（Radix 用 data-highlighted 标记 hover+键盘聚焦，只用 :focus 鼠标划过没反馈）。
6. `SelectItem` 加 `min-w-0`，`ItemText` 加 `block min-w-0 flex-1 truncate`，长选项不再把菜单撑宽。
7. `SelectTrigger` 基类 `flex` → `inline-flex`（默认 w-full 仍撑满；调用方传 w-auto 时才会真正按内容收缩，否则 `<td>` 里 `display:flex` + `w-auto` 会撑满整列），`[&>span]` 加 `min-w-0`。

顺带修的业务侧：`DomainMemberTable` 的 `value` 从 `|| undefined` 改为 `?? ""`（避免 controlled/uncontrolled 切换）；访客封禁目标下拉取消 disabled 占位项（恢复可重置）；角色下拉 `SelectValue` 加 placeholder 兜底、aria-label 改用 display_name。

### 真正的根因（第三轮，实测确认）

前两轮是盲修。这轮把 storybook 跑起来 + Edge headless CDP 实测定位，才找到真因：

**`SelectContent` 用了写死的 `max-h-72`（288px），没有消费 Radix 的 `--radix-select-content-available-height`。** Radix **不会自动限高**，只把可用空间放在 CSS 变量里等你自己用。结果：靠近视口底部打开时弹层按 288px 硬画，`bottom` 直接冲出视口（实测 557 > 489），底部选项被裁掉，且因为内容在视口外，滚动也看不见 → 用户看到的就是"弹层异常/看不全/滚不动"。

修复：`max-h-[min(var(--radix-select-content-available-height),20rem)]`。实测 content 高度 288→213、bottom 557→482（视口 489），完全收进视口。

同时补：
- `SelectPrimitive.ScrollUpButton/ScrollDownButton`：Radix 会给 viewport 注入 `scrollbar-width:none` 隐藏滚动条，不提供按钮的话长列表看起来"卡住"。
- `[&>span[data-placeholder]]:text-muted-foreground`：未选择态占位文字变灰，和已选值区分。

**验证方法（重要，以后复用）**：
- `packages/components` 起 storybook：`npx storybook dev -p 6011 --ci --quiet`

- **不要用 `--virtual-time-budget` 配 `--screenshot`**：它会打乱 Radix 依赖的 rAF 序列，弹层停在 `visibility:hidden`，截出来是空的，会误判成"弹层没渲染"。
- Safari 的 AppleScript 自动化被系统权限拦截（-10004），别走那条路。

## 修复重复 toast（同一失败弹两条）

根因：`apiClient` 响应拦截器对**所有** 4xx/5xx/网络错误都 toast 了，而调用方 catch 里又 `toast.error(apiErrorMessage(e))`，同一个失败弹两条。旧 `utils/toast.ts` 的 `alreadyToasted()` 只把 5xx/网络/白名单业务码当成"已提示"，4xx 反倒放行给调用方 → 4xx 必重复（旧测试还把这条 bug 当成期望行为写死了）。

改法（单一提示源 = 拦截器）：
- `apiClient.ts`：新增 `skipErrorToast` 请求选项（axios 模块增强）+ 在真正弹过提示的错误上打 `__toastShown` 标记；`APIClient.request` 里业务码 reject 时把标记带到 Error 上。silent 请求打 `__toastShown = false`（表示拦截器闭嘴、调用方要自己弹）。
- `utils/toast.ts`：`alreadyToasted()` 改为读 `__toastShown` 标记，兜底 `isAxiosError()`；`toastActionError()` 语义变成"拦截器已提示就静默"。
- 逐处替换 ~18 个 catch 里的 `toast.error(apiErrorMessage(...))` / `toast.error(err.message)` → `toastActionError(err, "业务兜底文案")`：域详情页(角色/访客/房间/踢人)、域页退出删除、房间列表删除、创建/编辑房间、邀请码重置、上传(附件/头像)。
- 保留自定义中文文案的接口改走 `skipErrorToast`：`guestJoin`（1013/1017 友好提示）、`sendEmailCode`（注册页按业务码映射）。后端 msg 是英文，这样前端文案不被拦截器的英文顶掉。
- 测试：重写 `utils/toast.test.ts`（6 例）覆盖"4xx 不重复弹 / skip 时仍弹 / 本地错误仍弹"。

## 修正：MyGo IPC 真实机制（覆盖层 HUD 接力）

之前记的"用 `window.__gospeakDesktop` 自定义桥 + 适配器拆参"是**错误假设**。已按 MyGo 官方文档改正：

- MyGo 向每个页面注入 `window.mygo`（`mygo-runtime` 提供类型）。前端用它：
  - `mygo.call(method, ...args)` 调 Go 绑定方法，方法名 = `<struct 小写>.<Method 首字母小写>`（如 `overlay.pushState`），参数**位置参数**，按 JSON 解码进 Go 方法签名。
  - `mygo.on(event, listener)` 收宿主事件；宿主侧用 `mygo.Broadcast(event, ...args)`（发到所有窗口页面）或 `mygo.Emit(window, event, ...)`（发到指定窗口）。
  - `isMyGo()` 判断是否 MyGo 窗口（而非 dev server 浏览器标签页）。
- 因此 `packages/desktop` 直接基于 `window.mygo` 封装，不需要自定义桥、不需要渲染前注入。`isDesktop()` 现 = `window.mygo?.isMyGo()`。
- 所有 capability 的 `bridge.invoke` 改为**位置参数**（window/tray/dialog/notification 之前用 `{value}`/`{options}` 对象传参，已全部改为位置参数；tray 命令名 `set_tooltip/set_menu` → `setTooltip/setMenu` camelCase 对齐 Go）。

## 覆盖层 HUD：显示成员 + 高亮发言人（接力架构）

覆盖层是 MyGo 的独立 WebView 窗口，**与主窗口各自独立 store 实例**，不能读主窗口的 socketStore；且不能自己连 socket/SFU（会双 join / DUPLICATE_IDENTITY）。所以采用**主窗口 → 宿主 → 覆盖层**接力：

## 桌面端：登录前可配置服务器地址（base URL，持久化 + 设置可改）

需求：桌面端在**登录前**就能指定要连接的服务器（base URL），值**持久化**，且能在**设置里修改**。

**连接模型（关键调研结论）**：全部网络都走 `apiClient`（axios，默认同源 base "/"）与 `wsClient`（WS worker 地址由 `getWSEndpoint` 经 apiClient 解析）。所以**只要让 apiClient 的 baseURL 运行时可配**，REST + WS 一处搞定；无任何裸 fetch/XHR 绕过。

实现（主窗口 → 宿主持久化 → 前端套用）：
- Go `app/desktop/server_config.go`：`ServerConfig` 服务，`GetBaseURL/SetBaseURL`，持久化到 `mygo.App.Path(mygo.PathUserData)/server-config.json`；`main.go` 绑定并在 WhenReady 里 `loadServerConfig()`（先于建窗）。
- SDK `packages/desktop/src/capabilities/server.ts`：`createServerConfig()`（命令 `server.getBaseURL` / `server.setBaseURL(url)`，位置参数）。
- Web `app/web/src/config/server.ts`：`initServerBase()`（启动时桌面端从宿主读取并套用）、`saveServerBase()`（套用+持久化）、`getServerConnectUrl()`（给 WS 首连用）。`apiClient` 新增 `setBaseUrl()`。
- `main.tsx` 渲染前 `void initServerBase()` —— 登录页的请求（登录/OAuth/域列表）就已打对服务器。
- `socketStore.connect()`：`VITE_SOCKET_URL` 为空时改用 `getServerConnectUrl()`（桌面端配置了 base 就首连到该服务器；浏览器同源行为不变）。此前桌面端首连会落到 `mygo://localhost/ws` 失败一次靠重连自愈，现已修正。
- UI：可复用 `components/common/serverUrlField.tsx`（失焦/回车保存），挂在 ①登录页卡片底部（`isDesktop()` 才显示，登录前可改）②设置页「桌面端」tab 新增「服务器」Section。修改即时生效于新请求；已建立的 WS 需重新登录切换（UI 有提示）。
- 浏览器构建完全不受影响（isDesktop false → 无字段、base 保持同源）。typecheck（desktop + web）均通过。

## （修正）桌面端连接模型：本地回环反向代理，绝不跨域

**最终架构（app/desktop/proxyserver.go）——本地回环反向代理：**
- 宿主启动 `127.0.0.1:<随机端口>` HTTP 服务，窗口加载该地址。页面与其 API/WS **完全同源**（同一个 origin）→ 无 CORS、Cookie 正常。

- 切换服务器 = `ServerConfig.SetBaseURL` → 持久化（`server-config.json`）→ 换代理 target → `reloadAllWindows()`（前后同 origin，原地刷新即可，无需重建窗口/TrustedOrigins）。

## 桌面端接入完成 + 端到端行为测试

**Go 服务方法体实现（对接 mygo v0.8.3）**：
- Window：Minimize/Maximize/Unmaximize/IsMaximized/SetAlwaysOnTop/SetTitle/Close，全部带 `context.Context` 首参 + `mygo.CallerWindow(ctx)` 作用于调用方窗口。
- Notification：`mygo.NewNotification` + `Show()` + `OnClick` → 统一事件 `notification.click`（payload=ID，Event[string]），前端 notification.ts 改为按 ID 匹配（不再是动态事件名）。macOS 首次 Show 自带权限询问，RequestPermission 返回 granted。
- Dialog：`mygo.DialogModule{}` Open/Save/Message，Parent=CallerWindow；filters 由 TS 的 `Record<name, exts>` 转 `[]FileFilter`。
- Tray：`mygo.NewTray`（WhenReady 里 ensureTray，图标取内嵌 dist 的 favicon-256.png），菜单 打开/退出（`mygo.NewMenu`+MenuItem.Click），SetMenu 动态构建 + `tray.menuClick` 事件回传 item ID，Show/Hide = ensure/Destroy。
- AutoStart：darwin 用 osascript System Events Login Item（enable/disable/isEnabled，路径为当前可执行文件），其他平台返回明确 unsupported 错误。
- Updater：Check 返回 nil（最新）、Install 报 unsupported（签名发布渠道打包时再接）。DeepLink：Open → `deeplink.open` 事件（scheme 注册在打包配置）。
